# ATML-PA4

This repository contains the implementation for ATML Programming Assignment 4 on
Qwen2.5 models. Task 1 (model compression, Qwen2.5-1.5B base) covers unstructured
magnitude, Wanda, and nonuniform pruning, a 2:4 structured-sparsity study, and
uniform, AWQ-style, and mixed-precision weight-only post-training quantization.
Task 2 covers exact attention, MQAR (multi-query associative recall), and KV-cache
compression. Task 3 covers speculative decoding with off-policy and on-policy LoRA
draft-model distillation. Code is developed locally and executed on Colab.

## Data

Data comes from [github.com/AbDu11aHHH/atml-pa4-datasets](https://github.com/AbDu11aHHH/atml-pa4-datasets)
at commit `6a0a9ec`, prepared via `setup_data.py --all`. The pinned upstream source

`data/local_source_revisions.json`.

## Reproduction (Colab, one L4, High-RAM)

1. Put the prepared data repository at `/content/drive/MyDrive/atml-pa4-datasets`
   (locked files in `data/public_locked/`, prefix banks in `data/prefix_banks/`).
2. Open each notebook and run its cells top to bottom; every cell prints `PASS` or `FAIL`.
   - `notebooks/01_task1.ipynb`: Task 1 (`python -m task1_compression.run_task1 run|aggregate`)
   - `notebooks/02_task2.ipynb`: Task 2 (`python -m task2_attention.run_task2 2a|2b|2c|aggregate`)
   - `notebooks/03_task3.ipynb`: Task 3 (`python -m task3_specdec.run_task3 <stage>`)
3. Results go to `/content/drive/MyDrive/atml_pa4_results/task{1,2,3}` (never to the repo).
   Every driver is resumable: it skips finished runs, and a failed run writes `error.json`
   while the driver continues. Each `aggregate` step writes `tables/` (CSV/JSON) and `plots/`.

Environment: `transformers==4.57.1`, `huggingface_hub==0.36.2` (pinned by the handout),
plus `requirements.txt`. Seeds: 6304 throughout (MQAR runs also use 6305 and 6306; Task 3 distillation uses 6304 and 6305).
CPU tests: `python -m pytest -q tests`.

## Deviations

(a) The staff `setup_data.py` passed `generator=` to `model.generate()`, which transformers
4.57.1 rejects (`ValueError: model_kwargs not used: ['generator']`). It was replaced with
`torch.manual_seed(<same per-prompt seed>)` before each `generate()` call.

(b) It left Qwen's `generation_config` `repetition_penalty=1.1` in effect. This was set to
`1.0` so the teacher/original-draft banks are pure temperature-1, top-p-1 sampling, as the
handout specifies. Patch: `docs/setup_data_patch.diff`.

(c) WikiText-2 raw rows are lines/paragraphs treated as separate documents: 437 windows
(~115 scored tokens each) for 50k tokens, versus 177 windows for C4. PPL is therefore not
comparable to published full-context WikiText-2 numbers.

(d) AWQ (Q2, and the AWQ-style quantizer reused by Q3) stores serialized FP16
compensating scales instead of folding the inverse scales into a neighbouring layer,
which is the alternative the handout permits. Each projection quantizes W·diag(α) and
keeps α in FP16, costing 2·d_in bytes per projection. Those bytes are counted in the
packed storage of Q2 and in the Q3 budgets, so Q3 is compared with Q2 like-for-like.
The folding in the original scaffold was removed: it applied the compensation twice,
folded through SiLU, scaled the wrong axis of the predecessor, and ignored GQA.

(e) Task 2B training data. Every run sees 144,000 examples, `make_example('train', K, regime, i)`
for i < 144,000, each exactly once. These are the same examples for every seed and architecture
with the same (K, regime). The seed controls initialisation and the order of the examples. The
streams are cached as `.npz` files on Drive.

(f) Task 2B implementations. Window, dilated and the local heads of B3 use SDPA with an explicit
dense boolean mask. Linear attention trains with the exact parallel (T×T) form; the recurrent
O(d²)-state form is unit-tested to be identical and is timed separately in the forward-only
sweep. These are correctness implementations, not efficient sparse or linear kernels (the
handout allows this when it is stated).

(g) Task 2B / B3. The intervention (`local_linear`: 2 local softmax heads with W=33 over an FP16
K/V buffer, plus 2 ELU+1 linear heads with FP32 state) was fixed before the B1/B2 results
existed. It is motivated by the linear-attention recall limits in Zoology (Arora et al. 2024)
rather than by our own observations. W=33 and FP16 for the local buffer are the adjustments
that make its persistent state exactly equal to the linear comparator's (16,896 B/layer). The
trainable parameter count is identical. The prediction and the development-selection rule are
recorded in `grid_manifest.json` before any training.

(h) Task 2A. The tiled reference keeps FP32 running statistics for FP16 inputs and skips fully
future key tiles. Its backward pass is plain autograd and stores every tile (not FlashAttention).
The dispatched SDPA kernel is read from CUDA-profiler kernel names.

(i) Task 2C quantisation convention. Each 64-element group stores an FP16 scale and an FP16
offset equal to the group minimum: x̂ = o + s·q, with no integer zero-point. The scaffold's
integer zero-point, clamped to [0, 2^b−1], collapsed every all-positive group. Both INT4 layouts
keep the trailing L mod 64 tokens in FP16, so the token-wise layout costs exactly M_b(L), the
same as the channel-wise one; the packed encoders verify this byte for byte. For accuracy, the
cache is dequantised to FP16 and used with ordinary SDPA. Packed bytes are the storage cost;
allocated GPU memory is reported separately. Inside one teacher-forced forward, newly appended
tokens attend to each other in FP16; completed groups are requantised after each forward.

(j) Task 2C retention and accounting. Retention is global, shared across layers and heads.
Every FP16-retained or FP16-selected position is charged a 2-byte index, including the
sink+recent rule, which could be described by two ranges instead. Question-aware scoring runs
the question suffix once over the full FP16 context cache with `q_proj` hooks. It applies RoPE at
the true positions, computes masked FP32 attention, then crops the cache back. This simplified
fixed policy is inspired by SnapKV (Li et al. 2024) and does not reproduce its head-specific
algorithm. Its cost is reported as scoring time. No retention parameter is tuned.

(k) Task 3 sampling. All of our own generation uses a direct softmax sampler (temperature 1,
top-p 1, top-k 0, repetition penalty 1.0) seeded with `torch.manual_seed`; Qwen's
`generation_config` is never consulted. The teacher pool, student banks and standalone accuracy
use batched left-padded sampling, seeded once per batch; the seed and batch row are recorded.
The exact-speculative bank, on-policy rollouts and every timed generation use batch size 1.

(l) Task 3 distillation. Off-policy uses one frozen teacher pool, built once and shared by both
seeds: 1 rollout per math prompt and 8 per short prompt. Visit v of a prompt presents rollout
v mod R, and the pool's generation time is charged in full to each off-policy run. Each
optimizer update has exactly 256 teacher-scored tokens (the last has 64). A response that
crosses an update boundary is split, and the remainder is re-scored by the student after the
step. The next presentation comes from the category whose quota is less filled.

(m) Task 3 timing. Speculative and target-only generation both CUDA-synchronise around every
phase so that the four-part per-round decomposition is exact. The measured throughput of both
therefore includes that synchronisation cost. The cost-model α is the pooled
accepted/examined fraction.

## Attribution

- The MQAR training stream is produced at run time by the supplied generator
  `scripts/mqar_generator.py` from the data repository, which is imported, not copied.
  `tests/test_mqar.py` contains a short standard-library copy of its algorithm so the CPU
  tests need no download.
- `task3_specdec/prefix_eval.py::select_positions` and the bank record format reproduce the
  position-sampling logic of the data repository's `scripts/setup_data.py`.
- RoPE for question-aware scoring uses `transformers.models.qwen2.modeling_qwen2.apply_rotary_pos_emb`
  and the model's own `rotary_emb`. LoRA uses `peft`. Models and tokenizers come from Hugging Face
  `transformers`.
- Algorithms are implemented from their papers, with no code copied: online-softmax tiling (Dao et
  al. 2022), causal linear attention (Katharopoulos et al. 2020), MQAR (Arora et al. 2024),
  SnapKV-style scoring (Li et al. 2024), KIVI-style KV grouping (Liu et al. 2024), exact
  speculative sampling (Leviathan et al. 2023), on-policy distillation (Agarwal et al. 2024;
  Zhou et al. 2024), and Wanda / AWQ for Task 1.
- Code was written with the help of an LLM coding assistant (Claude), as the handout permits.
